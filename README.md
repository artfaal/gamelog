# gamelog — «Хроника»

Игровой дневник Макса: https://games.artfaal.ru — одностраничная лента
пройденных игр с впечатлениями, кадрами, видео и обоями на весь экран.
Статика собирается из markdown-файлов своим генератором на node — без
фреймворков и сборщиков.

## Как это устроено

```
content/<slug>.md   ← записи, 100% рукописные (текст + YAML frontmatter)
content/media/      ← свои кадры и клипы (webm/mp4 в git не попадают)
cache/<appid>.json  ← машинная Steam-мета; пишет new.mjs, руками не трогать
                      (`released` — дата выхода строкой в формате Steam, как отдали:
                       хранится и сверяется make refresh, на странице не показывается)
cache/assets/       ← скачанные Steam-ассеты (вне git); качает сборка, чистить можно
scripts/build.mjs   ← сборка dist/ (лента + OG-стабы /e/<slug>/)
scripts/new.mjs     ← добавить игру: кэш + заготовка записи
scripts/refresh.mjs ← что разошлось со Steam (make refresh) и точечная правка поля кэша
scripts/steam-app.mjs ← форма cache/<appid>.json и походы в Steam: канон new + refresh
scripts/hours.mjs   ← сверка часов со Steam (make hours), ничего не пишет
scripts/suggest.mjs ← кандидаты в дневник (make suggest), ничего не пишет
scripts/timeline.mjs ← когда играл и до чего дошёл, по ачивкам (make timeline), ничего не пишет
scripts/steam-owned.mjs ← библиотека Steam одним запросом плюс общие креды и поход
                          в API: канон hours + suggest + timeline
scripts/video.mjs   ← проверка клипов по политике (make video)
scripts/video-policy.mjs ← пороги политики клипов: один канон для сборки и проверки
scripts/image.mjs   ← проверка кадров по политике (make image)
scripts/image-policy.mjs ← пороги политики кадров
scripts/image-size.mjs ← размеры jpeg/png из заголовка файла: один канон для сборки
                      (место под кадр в разметке) и для make image
scripts/siblings.mjs ← связки между заходами одной игры: кто первый, как подписать ссылку
scripts/ru.mjs      ← русские числа: разряды, склонение, десятичная запятая
scripts/test.mjs    ← проверки связок и разбора кадров (make test)
site/               ← styles.css, app.js, favicon.svg и fonts/, копируются в dist как есть
eslint.config.mjs   ← правила линта; прогнать отдельно — `make check`
```

Слаг файла — универсальный ключ записи и её якорь: `content/hades.md` →
`games.artfaal.ru/#hades` и OG-ссылка `games.artfaal.ru/e/hades/`
(карточка игры в телеграме, редирект в ленту).

## Установка

Нужен Node 20.19+ (требование eslint; `zlib.crc32`, которым тесты собирают png, приехал
в 20.15). В корне репо один раз: `npm ci`.

## Добавить запись

Очередь кандидатов — `add_game.md` в корне: план игр из дневника Макса со
статусами и цитатами. Только локальный файл (в `.gitignore` осознанно: репо
публичный, а в файле цитаты из личного дневника) — в клоне с GitHub его нет.

```bash
node scripts/new.mjs 1145360            # appid из URL страницы игры в Steam
# → cache/1145360.json + content/hades.md (заготовка, draft: true)
```

`new.mjs` не перезаписывает готовый кэш: запущенный на ту же игру второй раз, он
только делает заготовку записи (нужно для второго захода, см. «Возвращения»).
Причина запрета — записи ссылаются на кадры по номеру (`shots: [5, 0]`, `![](2)` в
моментах), а Steam порядок скринов меняет: перезапиши `shots` — и картинки в ленте
молча поедут, сборка этого не заметит. Обновить поле в готовом кэше — `refresh.mjs`.

Дальше — руками в `content/hades.md`:

```yaml
---
steam: 1145360          # опционально: без него медиа задаётся руками (см. не-Steam)
finished: 2026-07-12    # дата прохождения/дропа; tbd — «сейчас играю»
hours: 41               # число или tbd
score: 9                # 1–10 (шаг 0.5) или tbd; у дропа score нет — вместо него dropped: true
paused: true            # опционально: «отложил» — заход кончился, игра — нет (см. ниже)
verdict: Одна строка — вердикт крупным шрифтом.
shots: [0, 1]           # кадры записи: номера магазинных скринов или файлы из media/
clip: store             # store (микротрейлер) | media/my.webm | none
focus: 40               # опционально: смысловой центр обоев по горизонтали в % (по умолчанию 50)
logo: none              # у части игр логотипа и постера в Steam нет (404):
poster: none            # logo: none — имя текстом, poster: none — обои и полка из кропа hero
                        # logo: dark — вместо none: логотип у игры тёмный, тень под ним светлая
platform: switch        # опционально, пометка для не-Steam платформ
draft: true             # убрать перед публикацией
---
Текст впечатления. Обычный markdown. ||Это спойлер — блюр до клика.||

## Моменты
### Название момента
![Подпись кадра](2)
Текст к конкретному кадру. Ссылка в картинке — номер магазинного скрина,
путь media/my.jpg или видео media/my.webm / media/my.mp4 (играет прямо в моменте).

### Финал {spoiler}
![Финальный кадр](4)
Момент целиком заблюрен до клика «спойлер — показать».
```

Кадры и клипы записи читатель листает в лайтбоксе — стрелками, кликом по краям
кадра или тапом по бокам на телефоне; нераскрытый спойлер туда не попадает.

Мета записи — лента чипов (дата, часы, платформа, ссылки на другие заходы);
есть `steam:` — добавляется чип со ссылкой на страницу игры в магазине.

Оценка — медаль на верхней кромке панели: кольцо заполнено пропорционально оценке.

На узком экране (до 48rem) медаль на кромку не помещалась и уезжала в начало
строки неуклюжим кружком — там она уступает место чипу оценки, первому в ленте
меты: цифра, шкала 0–10 и «из 10». Сама медаль из разметки не исчезает, а
прячется в sr-only: подпись оценки для скринридера живёт в ней, чип её только
дублирует на экране и потому `aria-hidden`.

Обои записи на узком экране — не hero: широкий баннер 3,1:1 влезает в портретный
экран пятой частью своей ширины, и центр файла почти никогда не совпадает с
сюжетом кадра. До 48rem на его место встаёт вертикальный постер игры — тот же
2:3, что на полке, целиком и прижатый к верху; вшитое в постер название заменяет
логотип-оверлей. До низа экрана постер не достаёт, и полоса под ним набирается из
него же: снизу — его нижняя кромка, растянутая вниз, поверх — его копия в той же
геометрии под блюром, открытая маской. Один файл и одна геометрия на все слои:
низ кадра теряет резкость сам, а не упирается в чужое размытое пятно, и второй
загрузки при этом нет. Панель записи начинается ровно на низе постера
(`calc(150vw - 100svh)`), поэтому текст выезжает раньше и всегда на растворённом,
а не поверх арта.

Логотип игры лежит поверх арта с тёмной тенью — она отделяет светлый логотип от
светлого кадра. Логотипу, нарисованному чёрным (Atomic Heart), такая тень добавляет
черноты, и на светлом арте он с фоном сливается: `logo: dark` во фронтматтере меняет
её на светлую. Признак ставится руками — записей десятки, автор смотрит каждую
глазами, и автоматика тут дороже своего результата.

На стыке записей та же логика: хвост уезжающей дотаивает в цвет страницы, а верхняя
кромка приезжающей размыта и из этого цвета всплывает — иначе новый постер въезжает
в размытый хвост предыдущего резаным краем. Это правило общее для всех обоев на
узком экране: у записи без постера кромка кадра растворяется так же.

Шов намеренно разный по ширинам, и это выбор автора, а не недоделка: на телефоне
постер до низа экрана не достаёт, и полосу под ним всё равно приходится растворять,
а на широком экране арт занимает кадр целиком — там резаная кромка читается как
разделитель записей. Растворение шва живёт только в мобильном блоке `styles.css`.
Постера нет (`poster: none`) — остаётся кроп hero, и тогда кадр наводится руками:
`focus: 40` — смысловой центр по горизонтали в процентах. На широком экране тот же
`focus` двигает кроп hero точно так же.

Файл постера сборка кладёт в атрибут `data-poster` записи, а переменную `--poster`
для размытых слоёв ставит `site/app.js` на подходе к записи. Инлайновый `url()` в
переменной браузер качает немедленно, мимо `loading="lazy"` — все постеры ленты
приезжали на первый экран. Так же, на подходе к записи, и по той же причине
подставляется кадр-заглушка клипа (`poster` у `<video>` качается даже при
`preload="none"`). Размен: пока JS не выполнился, у клипов нет заглушки, а на узком
экране нет обоев — без JS в ленте и так не работают лайтбокс, полка и автоплей.
Записи в ленте рисуются все и с самого начала: высота каждой известна сразу и больше
не меняется. Это не роскошь, а лечение живого дефекта. Раньше запись вне экрана
не раскладывалась (`content-visibility: auto`), её место держала заглушка `250svh`,
а настоящая высота у записей — от 1747 до 4267 px. В момент первой раскладки разница
сдвигала всё, что ниже. При чтении снизу вверх этот момент приходится на запись **выше**
вьюпорта, и Safari, в отличие от Chrome, такой сдвиг не компенсирует: контент уезжал
под пальцем на 764, 434, 378 px — замерено на живой ленте. Отсюда «в Chrome всё хорошо»
и «воспроизводится только на холодном кеше».

Ни точная заглушка (сборка считала её по объёму текста), ни ранняя раскладка дефект
не лечили: они меняли момент и величину скачка, но не убирали сам скачок. Оба механизма
сняты 20 августа 2026, вместе с ними — `content-visibility`.

Трафик, который держало то правило, держит гейт в `app.js`. У всех записей, кроме первой,
адрес снимается: у кадров, обоев, логотипа, картинок в тексте и у `<source>` узкого
экрана, — и возвращается на подходе тем же наблюдателем, что будит постеры и заглушки
клипов. Обои и логотип будит сама запись, а не они: на узком экране логотип скрыт, бокс
у него нулевой, и пересечения по нему не случилось бы никогда. Место при этом занято
заранее — у кадров атрибутами `width`/`height`, у обоев стилями, — поэтому снятый адрес
геометрию не двигает. Первая запись остаётся с адресами: она на экране.

Замер на окне 480×850 с холодным кешем: первый экран — шесть файлов, дальше по ленте
кадры приезжают к моменту подхода; за проход снизу вверх высота записи меняется один раз
на 2 px против прежних шестнадцати изменений на сотни. В разметке адреса остаются, так
что без JS лента просто загрузит все картинки сразу — деградация, а не пустые кадры.

Программной прокруткой (`scrollBy`) этот рывок не воспроизводится ни в Chrome, ни
в Safari — только живой прокруткой. Проверять правки тут можно лишь руками на живой ленте.

## Полка

Окно навигации по дневнику (кнопка ☰): поиск, фильтр и сетка постеров группами.
Открывается на активной записи — той, что читатель сейчас видит в ленте.

Кнопка ☰ — обычный элемент шапки, а не таблетка поверх неё. Фикс-кнопкой она выпирала
за нижнюю кромку полосы (её бокс шёл до 58 px при шапке в 56), забирала у шапки 12 rem
паддинга под себя и оставалась висеть одна на арте, когда шапка уезжала: правило
`fabs-away` для неё было только на узком экране. В потоке шапки она едет и уезжает
вместе с ней, а фон и блюр берёт у полосы. На узком экране шапка встаёт сеткой —
вордмарк и ☰ верхней строкой, «где я сейчас» и счётчик под ними: флекс с переносом
ставил кнопку туда, куда попадал перенос. Высота шапки от кнопки не выросла ни на
одной ширине. Освободившийся правый нижний угол забрала кнопка «наверх» — левым она
стояла только потому, что правый занимала полка.

Та же сетка стоит стеной в хвосте ленты — иначе лонгрид на 38 тысяч пикселей
заканчивается ничем. Узел один: `site/app.js` переносит его в диалог на открытии и
возвращает в стену на закрытии, второй разметки нет. В стене заголовки групп сняты
(на широком экране месяц по одной обложке рвал бы её на строки), а набранный запрос
снимается на закрытии полки — иначе стена показывала бы одну обложку из семнадцати.
Выбранные чипы фильтра, наоборот, переживают закрытие: запрос разовый, фильтр — режим
просмотра, и стена показывает тот же срез, о котором говорит точка на кнопке ☰.

Поиск по названию и по тексту записи: набор сужает сетку, Enter ведёт к лучшему
совпадению, стрелки перебирают остальные, `/` открывает полку сразу в поиске.
Совпадение ищется по началу названия и слов, инициалам (`sts` → Slay the Spire 2)
и слагу, последним — по тексту; русская раскладка учитывается (`фещьшс` → Atomic
Heart). Текст едет в карточку атрибутом `data-text` (весь корпус — десяток
килобайт, отдельный индекс дороже): основной текст записи плюс заголовки и тексты моментов,
через `plain()` в `build.mjs`. Спойлеры вырезаны вместе с содержимым, момент
`{spoiler}` не индексируется целиком — из-под блюра поиск ничего не находит.

Фильтр — свёрнутый блок с рядами чипов: оценка, статус, часы, «есть кооп» и моменты,
жанр. Чип кооператива назван «есть кооп» намеренно: признак приезжает из категорий
Steam и говорит о самой игре, а был ли этот конкретный заход совместным, запись не знает.
Раскрыт, если хоть один чип нажат (в подписи — сколько): на телефоне развёрнутые
ряды съедали пол-окна, а до постеров надо было доскроллить. Внутри ряда чипы
складываются по ИЛИ, ряды между собой — по И: `7+` и `40+ ч` дают «во что залипал
и что понравилось». Ряд оценки — исключение (`solo` в `CHIPS`): пороги в нём
взаимоисключающие, потому что `9+` и `8+` разом всё равно дают просто `8+`.

Хвосты — «во что вернуться и что доиграть» — достаются двумя чипами. «Без оценки»
стоит четвёртой ступенью в ряду оценки, на той же оси: это заход, по которому вердикта
ещё нет. Дроп в него не попадает — у дропа оценки нет по устройству, а не «пока».
«Незакрытое» в ряду «ещё» — ярлык: отложил ∪ сейчас играю одним нажатием, тот же срез,
что руками собирается из двух чипов статуса. Ряд статуса остаётся точным инструментом,
ярлык живёт поверх него.

Чипы разные, хоть на нынешнем контенте и совпадают: «без оценки» смотрит на оценку
(`noVerdict` в `site/app.js`), «незакрытое» — на статус. Пройденная запись с `score: tbd`
попадёт в первый и не попадёт во второй; отложенная с числовой оценкой — наоборот.
Сборка обе комбинации разрешает.

Чип, под который не подходит ни одна запись, прячется — и не оживает из ссылки со срезом:
нажатым он дал бы пустую сетку без видимой причины, а ссылка переживает наполнение дневника.
Ссылка, собранная руками, взаимоисключающий ряд обойти всё же может (`#f=score9,scorenone`
подсветит оба порога и сложит их по ИЛИ) — оставлено осознанно: интерфейс такую не выдаёт,
а результат остаётся осмысленным срезом.
Поиск работает уже по отфильтрованному. Набранное сбрасывается на каждом открытии
полки, выбранные чипы — нет: запрос разовый, а фильтр — режим просмотра. Поэтому
включённый фильтр виден и снаружи: кнопка ☰ получает точку и другой `aria-label`.
Ничего не нашлось — сетка говорит это словами и даёт сброс запроса и чипов разом.
Оценка и часы подписаны прямо на постере, иначе непонятно, почему запись попала в срез.

Срез отдаётся ссылкой: выбранные чипы уезжают в hash (`#f=score9,hours40`,
`history.replaceState` — срез не шаг истории), открытие такой ссылки открывает полку
с тем же срезом. Якорь записи (`#hades`) остаётся якорем: срез узнаётся по префиксу
`f=`, больше hash ни на что не разбирается.

Порядок сетки — дата, оценка или часы. Не по дате — заголовки групп сняты: карточки
перемешаны, и подпись группы врала бы. Переставляет карточки CSS-свойство `order`,
узлы остаются на месте — потому сетка и собрана одним гридом, а заголовки групп
стоят в нём строкой на всю ширину.

Группы сетки — годы, но пока в записях меньше двух закрытых лет (`YEARS_FOR_YEARS`
в `build.mjs`, закрытый = любой, кроме текущего), группировка идёт по месяцам:
на молодом дневнике год — это одна куча на всю сетку. Режим временный и переключится
сам, когда дневник переживёт второй закрытый год.

Сетка берёт лёгкий постер (`posterSmall` в кэше — тот же `library_600x900` без
`_2x`): карточка выходит 94 px шириной, ретиновому файлу там нечего показать,
а весит он втрое больше. Поля нет в кэшах, записанных раньше, чем оно появилось, —
сборка выводит лёгкий постер из ретинового сама (`posterSmallOf` в `steam-app.mjs`),
переписывать готовые кэши ради одного поля нельзя. Постеры полки начинают грузиться
в первую же паузу после того, как читатель тронул ленту. Сама сетка лежит не в диалоге,
а в хвостовой стене (`app.js` переносит узел в `<dialog>` только на открытии), и от
первого экрана её отделяет вся лента — нативный `loading="lazy"` до неё не доходит,
и сетка собиралась на глазах у того, кто открыл полку сразу.

Пороги чипов заданы в `scripts/build.mjs` (список `CHIPS`) и уезжают в разметку
атрибутами `data-k/min/max/v` — `site/app.js` их только применяет и второй копии
порогов не держит. Жанры и кооп приходят из Steam: `new.mjs` кладёт их в
`cache/<appid>.json` тем же запросом, которым берёт остальную мету. Ряд жанров в
полке собирается из того, что реально есть в записях.

Не всё, что Steam зовёт жанром, им является: «Early Access» — стадия релиза, а в
ряду чипов она встаёт наравне с RPG. Такие вычёркивает стоп-лист `GENRE_STOP` в
`build.mjs`. Режет при сборке, а не в `new.mjs`: кэши уже записаны, и
переписывать их ради этого нельзя. Жанры, заданные руками во фронтматтере, стоп-лист
не трогает — там автор пишет осознанно.

## Слова интерфейса

Обвязка говорит словами дневника, а не репозитория: «обложки и кадры», а не
«ассеты»; «кадры и видео», а не «медиа». Статус игры называется одинаково во всех
местах — «сейчас играю»; короткое «играю» остаётся только тегом на постере полки,
где полная форма встаёт в две строки и закрывает обложку. Доли пишутся словом:
«8,5 из 10», «1 из 2» — не через слэш. Десятичный разделитель везде запятая, и дробное
число идёт с родительным единственного: «41,5 часа», а не «41.5 часов» (`scripts/ru.mjs`).

Подпись читателю даётся там, где она что-то добавляет: у магазинных кадров alt
пустой (номер и имя игры уже сказаны заголовком и счётчиком), у своих кадров и
моментов подпись пишет автор — она же работает и как подпись в лайтбоксе.

## Кнопки: рамка означает «нажимается»

Факты записи — оценка, дата, статус, часы, платформа — стоят в ленте меты плоско:
иконка и текст, без рамки и подложки. Пилюлю носит только нажимаемое: ссылка на другой
заход, плашка магазина, «поделиться», чипы фильтра на полке. До этого пилюлями было всё
подряд, и строка не отвечала на «что тут можно нажать» — дата выглядела кнопкой ровно
так же, как ссылка на соседнюю запись.

Список нажимаемого живёт в одном правиле (`site/styles.css`, селектор с `padding`,
`border` и `background` после базового `.chip`) — это же единственное место, где
записано, что в дневнике кнопка. Плоскому чипу отдана иконка в полную силу: полупрозрачной
она держала строку в паре с рамкой, а без рамки осталась одна. Отступ между чипами на
телефоне режется до `--space-xs`: лишние 4 px разносили ленту записи с оценкой на третью
строку.

Кнопки и чипы отвечают на наведение одинаково: рамка и текст уходят в янтарь. Правило
одно (`site/styles.css`, «один жест на всё нажимаемое») и накрывает чип-ссылку, плашку
магазина, «поделиться», кнопку полки, «наверх», чип фильтра и крестик диалогов. До этого
жестов было шесть: ореол 18 px у плашки Steam, серая рамка у чипа фильтра, один цвет
иконки у «поделиться», плотнеющий фон у крестика — и в одной строке меты соседние кнопки
вели себя по-разному. Плашка Steam светится своим фирменным цветом: жест тот же, а цвет
у неё бренда.

Правило — про кнопки, а не про всё кликаемое. Картинка, карточка полки и ссылка в тексте
отвечают по-своему и намеренно: кадр под лупой светлеет, постер полки берёт серую рамку
(янтарная там занята — ею отмечена активная запись), ссылка в прозе и в подвале красится
без рамки, которой у неё нет. Стрелка лайтбокса пришла к общему жесту сама.

Высота у всего нажимаемого одна — 2 rem: чип, плашка магазина, «поделиться», кнопка
полки. Раньше «поделиться» стояла на 3 px выше соседей по той же строке.

Наведение живёт под `@media (hover: hover) and (pointer: fine)`: на тачскрине `:hover`
залипает после тапа, и кнопка остаётся подсвеченной, пока читатель не тронет другую.

Системных подсказок (`title`) в мете нет: жёлтая плашка ОС приезжает через секунду и
рисуется мимо стиля дневника. Имя действия читателю с экранным диктором даёт `aria-label`,
он и остался. `title` на карточке полки — другое: там он подписывает обложку, а не кнопку.

## Кэш Steam: что разошлось

Steam правит страницы игр — меняет описание, добавляет скрины, подменяет ролик.
Кэш об этом не знает:

```bash
make refresh    # диф по всем cache/*.json, ничего не пишет
```

Пишет точечно и только названные поля:

```bash
node scripts/refresh.mjs 668580 --field genres,coop
```

`shots` и `micro` за этим флагом не пишутся: именно они ломают записи молча.
Нужны — `--unsafe` вдобавок; подтверждения скрипт не спрашивает (флаг и есть
подтверждение), но вместе с записью печатает карту сдвига («№0→№2, №4→нет») и
перечисляет записи, которые ссылаются на эти номера, — их придётся перепроверить
глазами. Массово (`--all`) их не переписать никогда. Записи без `shots:` во
фронтматтере в этот список тоже попадают: сборка берёт им первые два кадра сама,
и сдвиг порядка ломает их так же молча.

Метка `?t=…` в хвосте ссылок на скрины расхождением не считается: Steam меняет её
сам по себе, а сборка кэширует ассет по имени файла.

## Часы: сверка со Steam

Часы в записи ставит человек, но искать цифру в профиле руками не надо:

```bash
make hours
```

Скрипт тянет наигранное из Steam Web API и сверяет с записями: где сходится, где
разошлось, где стоит `tbd` и есть что проставить. У игр с несколькими заходами
сравнивается сумма — Steam знает только общий налёт. Ничего не пишет: `md`
остаётся рукописным, решение за автором.

Ключ и steamid — `~/.skill-secrets/game-compass.env` (канон там же, где профиль
Макса; в Bitwarden). Steam из этой сети бывает недоступен напрямую:
`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=… make hours`.

## Кандидаты в дневник

Обратный вопрос к тому же запросу: во что наиграно, а записи до сих пор нет.

```bash
make suggest             # от 20 ч
node scripts/suggest.mjs --min 50
```

Строка — название, часы, дата последнего запуска и appid, готовый к
`node scripts/new.mjs <appid>`. Порог по часам библиотеку на 570 игр не приручает
(верх занимают десятилетней давности Dota 2 и CS2) — приручает колонка даты, по ней
же отсортирован `add_game.md`. Помеченные `оч.` в очереди уже стоят; это метка, а не
фильтр — `add_game.md` в клоне с GitHub нет, и от его отсутствия список не меняется.

Ничего не пишет, как и `hours`: очередь ведёт человек.

## Когда играл: по ачивкам

Библиотека знает про игру две вещи — сумму часов и дату последнего запуска, и обе
врут о заходе. «Последний запуск» бывает десятиминутным любопытством спустя годы
после прохождения: у Drova это май 2026, а играл автор в новогодние каникулы
2024-го. Ачивки помнят каждую дату по отдельности.

```bash
make timeline APPID=1245620
node scripts/timeline.mjs 1245620
```

Отчёт разложен на заходы: цепочка режется там, где между соседними ачивками пауза
длиннее двух месяцев (`GAP_DAYS`), — иначе у Terraria с набегами 2015…2025 «окно
захода» вышло бы длиной в десять лет. По каждому заходу — границы, плотные дни
(где ачивок за сутки больше одной, там и сидели) и хвост — концовки и последние
боссы падают под конец, по ним и ставится `finished`. Отдельно — невыбитое: оно
отвечает на «а этого босса я добил?», когда человек уже не помнит.

Названия берутся русские (`l=russian`); нет перевода — Steam сам отдаёт английский.

Достижений у игры может не быть вовсе — Steam отвечает на это кодом 400, и скрипт
говорит про ачивки, а не про сеть. Ничего не пишет, как и `hours` с `suggest`.

## Клипы: политика качества

Один стандарт на все видео, чтобы страница не весила как игра:

| | Предел | Почему |
|---|---|---|
| разрешение | 1920×1080 | выше на странице не видно, вес растёт вдвое |
| кадры | 30 fps | клип — атмосферная вставка, не геймплейный разбор |
| длительность | 35 с | микротрейлер Steam ~30 с, свои моменты короче |
| вес | 0,5 МБ/с и не больше 20 МБ | ≈4 Мбит/с — на глаз чисто, мобильный интернет тянет |
| faststart | обязателен у mp4 | без него браузер не начинает играть, пока не дотянет файл до конца. У webm свойства нет: это порядок боксов MP4, и проверка его не спрашивает |

Ужимаем по обеим сторонам: проверка ругается и на высокий кадр, а `'min(1920,iw)':-2`
портретный 1080×1920 оставлял как есть. `min` по каждой стороне не даёт растянуть мелкий
клип до предела, `decrease` держит пропорции, `force_divisible_by=2` — потому что libx264
с yuv420p не берёт нечётную сторону. Проверено на 1000×999, 1080×1920, 1920×1200 и 640×360.

Канон пережатия — crf 23 с потолком битрейта: crf сам по себе на боевом 1080p
вылезает за политику, потолок держит вес, не трогая спокойные сцены.

```bash
ffmpeg -i ИСХОДНИК -vf "scale='min(1920,iw)':'min(1080,ih)':force_original_aspect_ratio=decrease:force_divisible_by=2,fps=30" \
  -c:v libx264 -crf 23 -maxrate 3.8M -bufsize 7.6M \
  -preset slow -pix_fmt yuv420p -c:a aac -b:a 96k -movflags +faststart out.mp4
```

```bash
make video       # отчёт: что не по политике, с готовой командой пережатия
make video-fix   # то же + проставит faststart без пережатия (поток копируется)
```

Пережимает человек и только из исходника: повторное сжатие уже сжатого съедает
картинку. Прод-сборка ругается на клипы тяжелее 20 МБ, но не падает — вес не
повод не опубликовать запись. Цифры политики лежат в `scripts/video-policy.mjs`,
таблица выше их описывает.

## Кадры: политика веса

Та же идея для своих jpg и png в `content/media`:

| | Предел | Почему |
|---|---|---|
| разрешение | 1920×1080 | разметка ленты задаёт кадру этот размер, лайтбокс жмёт по высоте экрана |
| вес jpg | 175 КБ/Мпикс | ≈360 КБ на полный 1080p; у записи бывает 4–6 кадров |
| вес png | 150 КБ жёстким потолком | png в media — логотипы и постеры, плоская графика; плотность для неё врёт |

Вес jpg меряется плотностью, а не жёстким потолком: в `media` лежат и полные
1080p, и узкие кропы — мерить их одним числом килобайт значит равнять кроп с
полным кадром.

```bash
make image       # отчёт: что не по политике, с готовой командой пережатия
```

```bash
ffmpeg -i ИСХОДНИК -vf "scale='min(1920,iw)':'min(1080,ih)':force_original_aspect_ratio=decrease" -q:v 4 -pix_fmt yuvj420p out.jpg
```

`--fix` у кадров нет намеренно, в отличие от клипов: у видео он проставляет
faststart, не трогая поток, а у картинки правки без потери качества не осталось —
метаданных в кадрах нет, а lossless-оптимизация jpeg даёт 2%, то есть нарушитель
остаётся нарушителем, зато оригинал переписан. Цифры — в `scripts/image-policy.mjs`.

Размеры кадра сборка и проверка читают одним и тем же разбором заголовка файла
(`scripts/image-size.mjs`, jpeg SOF и png IHDR): сборке они нужны, чтобы зарезервировать
место в разметке — свои кадры бывают узкими кропами, и обещать браузеру 1920×1080 за них
нельзя. Раньше проверка кадров спрашивала то же самое у `ffprobe` и без него падала.

Сборка вес кадров не проверяет (в отличие от клипов): страницу они утяжеляют не так
резко, а `make image` дешевле, чем ещё один проход по файлам на каждой сборке.

Проверить и опубликовать:

```bash
make check     # линт (eslint) — сам гоняется перед сборкой и деплоем
make test      # связки заходов и разбор размеров кадра
make drafts    # собрать dist/ с черновиками, не поднимая сервер
make serve     # локально с драфтами: http://localhost:8480
make deploy    # прод-сборка (без драфтов) + rsync на orion
```

Тонкие правила, которых в живом контенте пока нет, проверяет `make test` (встроенный
`node:test`, ни одной зависимости): подписи связок между заходами — их восемь сочетаний
исхода и времени, — разбор размеров кадра и русские числа (склонение часов, десятичная
запятая). Всё остальное проверяет сама сборка на
реальных записях, поэтому в тестах этого нет.

Сборка валидирует контент. Кривая дата, отсутствующий score без `dropped: true`,
несуществующий номер скрина — прод-сборка падает и указывает на файл (драфт с
ошибками просто пропускается с предупреждением). Пустая прод-сборка не деплоится.

`make deploy` перед rsync ещё раз грепает собранный `dist/index.html` — два сторожа
подряд, оба ловят регресс в собранной разметке, а не на живом сайте. Первый — на
`poster=` у `<video>`: с ним кадр-заглушка клипа качается сразу, а не на подходе к
клипу, и тянет за собой лишние мегабайты на первый экран. Второй — на обои с
`loading="eager"`: пробуждение обоев следующей записи живёт в `site/app.js` и меняет
атрибут только на подходе к записи, а не жадно с самого начала — иначе десятки
мегабайт артов уедут на первый экран. Оба дефекта молча возвращаются при любой
правке `build.mjs`. Найден любой — деплой падает с сообщением до rsync, до прода
ничего не долетает.

Правку вёрстки не сдавай по общему кадру страницы: сними кроп изменённого элемента
с увеличением и по кадру на каждое значение, которое он умеет принимать (целое,
половинное, `tbd`, дроп). Общий скриншот такие дефекты не показывает.

Steam-ассеты (обложки, скрины, клипы) сборка скачивает в `cache/assets/` и
кладёт на сайт — медиа раздаётся со своего домена, и читатель не зависит от
доступности Steam CDN.
Сеть нужна один раз на каждый новый ассет; скачанное кэшируется. За прокси:
`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=… make build`.

Шрифты — по той же причине свои: `site/fonts/`, шесть woff2, подключены через
`@font-face` в `styles.css`. `fonts.gstatic.com` из России режется, и вместо
Cormorant читатель получал бы Times New Roman. Шесть файлов, а не четырнадцать,
потому что на запрос нескольких весов Google отдаёт один вариативный файл: пара
latin + cyrillic на семейство. Расширенных наборов (`latin-ext`, `cyrillic-ext`)
нет — символы вроде `→ ↗ ☰` не лежат ни в одном из них и рисуются системным
фолбэком. В git шрифты, в отличие от Steam-ассетов, попадают: их полторы сотни
килобайт против десятков мегабайт кэша ассетов, зато сборка не зависит от
доступности хоста, который как раз и режется.

`og:image` главной — коллаж `dist/og.jpg`: три свежих постера в кадр 1200×630,
склейка ffmpeg на сборке. Ссылку на дневник кидают в чат, и карточка должна
показывать дневник, а не одну случайную игру. Нет ffmpeg или постеров меньше трёх —
сборка не падает, печатает предупреждение и оставляет `og:image` обложкой первой
записи. У стабов `/e/<slug>/` карточка своя — там как раз нужна одна игра.

`dist/feed.xml` — RSS 2.0 по опубликованным записям: `link` и `guid` ведут на стаб
`/e/<slug>/`, `pubDate` — дата из `finished` (у «сейчас играю» её нет, элемент опускается),
описание — то же, что в OG-карточке стаба. Черновики в фид не идут: их нет в прод-сборке.
Ссылка на фид — в `<head>` главной (`<link rel="alternate">`) и в футере: с волны 5
фид видели только читалки, а читатель о нём не знал.

Сборка кладёт в `dist/` ещё `sitemap.xml` и `robots.txt`. В sitemap один URL —
корень: стабы `/e/<slug>/` живут ради OG-карточек в телеграме, их `canonical` ведёт
в ленту, и в индексе им делать нечего. `lastmod` — самая свежая дата `finished`.

## Сейчас играю и «пока не знаю»

`tbd` — допустимое значение для `finished`, `hours` и `score`: пишется вместо даты
или числа, сборка не ругается. Заготовка от `new.mjs` уже приходит с тремя `tbd`.

`finished: tbd` — это ещё и статус «сейчас играю»: запись встаёт в начало ленты,
получает чип в мете и попадает в группу «сейчас» на полке. Часы с `tbd` не
выводятся в мете, медаль оценки — тёмная, с прочерком вместо цифры. Закончил —
заменил `tbd` на дату, часы и оценку.

Счётчик в шапке ленты считает все игры и все часы: дропы и «сейчас играю» идут
в него наравне с пройденными, часы `tbd` в сумму не попадают — их просто нет.
Шапка липкая и рядом со счётчиком показывает, где читатель сейчас: «5 из 17 ·
Gothic 1 Remake». Значение ставит тот же наблюдатель, что подсвечивает карточку
на полке, — второго вычисления активной записи нет.

Верх постера шапка не накрывает: отъехав от начала дальше 200 px и продолжая ехать
вниз, читатель получает класс `fabs-away` на `<body>` — с ним уезжают и таблетка
«наверх», и сама шапка (а с ней кнопка полки и указатель «где я сейчас»: он интересен, когда читатель
остановился или поехал назад, — тогда он и возвращается). Первое же движение вверх
возвращает всё обратно; направление считает один обработчик прокрутки в `app.js`.

Дроп и `finished: tbd` несовместимы: дроп уже случился, дата у него есть.

`paused: true` — третий исход захода, «отложил»: играть перестал, но не бросил (ждёт
релиза, вернётся позже). Без этого поля такая запись числилась бы пройденной — «пройдено»
в сборке это всё, что не дроп и не «сейчас играю». Дата у неё есть, но это дата последнего
захода, а не финала, поэтому рядом с ней встаёт чип «отложил»; на полке запись получает
метку «пауза» и свой чип статуса. С `dropped: true` и с `finished: tbd` не сочетается —
сборка ругается, как и на дроп с `finished: tbd`.

У дропа вместо оценки — медаль со словом «дроп», а кадры и клип по умолчанию не подставляются:
запись выходит текстом. Нужны — задай `shots:` и `clip:` руками, дальше всё как у
обычной записи, включая моменты.

## Возвращения к игре

Один файл = один заход. Второй заход — второй файл с тем же `steam:`
(для не-Steam — с тем же `game:`): `atomic-heart-2024.md` (дроп) +
`atomic-heart.md` (прошёл). Заготовка второго файла:
`node scripts/new.mjs 668580 --slug atomic-heart-2024` — кэш игры уже есть, скрипт
его не тронет и в Steam не пойдёт, только напишет заготовку. Связки «первый заход —
дроп в 2024 ↗ / вернулся и прошёл в 2025 ↗» генератор строит сам.

## Не-Steam игры (Switch, PSN…)

`steam:` не указывается, минимум — своя обложка:

```yaml
name: The Legend of Zelda — Tears of the Kingdom
hero: media/zelda-hero.jpg    # обязательна (широкий арт)
logo: media/zelda-logo.png    # нет — имя рисуется текстом
poster: media/zelda-poster.jpg # нет — обои на узком экране и полка из кропа hero
platform: switch
```

У не-Steam записи нет и жанров: без них она молча выпадает из жанровых чипов на
полке. Жанры задаются руками списком — своими словами, таксономия Steam не обязательна:

```yaml
genres: [RPG, Adventure]
```

Мультиплатформа, которая есть в Steam, указывается через `steam:` — даже если
играл не там.

## Инфраструктура

- Хостинг: orion, `/var/docker/compose/gamelog/data/` (nginx + caddy-label) —
  → INFRA-DOCS `servers/orion.md`
- DNS: A-запись `games` в Cloudflare (скилл cloudflare-dns)
- Деплой: `make deploy` (сборка + rsync), CI нет намеренно
- Заголовки ответа задаёт `nginx.conf` рядом с `docker-compose.yml` на orion
  (в репозитории его нет — правка живёт на сервере):
  - `gzip on` с `gzip_proxied any` для `text/css application/javascript
    image/svg+xml` от 1 КБ. `gzip_proxied any` обязателен: впереди Caddy, он
    ставит заголовок `Via`, а при значении по умолчанию nginx проксированные
    запросы не жмёт. HTML nginx жмёт всегда, его в списке типов не пишут.
  - `Cache-Control`: `/a/` и `/fonts/` — `public, max-age=31536000, immutable`
    (имя файла стабильно, ассет под тем же именем не перезаписывается);
    `/` и `*.html` — `no-cache`, HTML меняется каждой сборкой.
  - Файл смонтирован отдельным файлом, поэтому после правки нужен
    `docker compose up -d --force-recreate`: `nginx -s reload` читает старый inode.

## История дизайна

Дизайн — вариант «Свиток», выбранный после пяти итераций прототипа
(варианты A…J, ветка `prototype`, живой архив: https://pub.artfaal.ru/gamelog-proto/).

Мета и оценка — вариант «медаль на кромке», выбранный после двух раундов
отдельного прототипа: лента чипов вместо строки с точками, оценка — кольцо,
приколотое к верхней кромке панели. Для узкого экрана медаль позже заменена
чипом со шкалой — отдельный раунд прототипа из четырёх вариантов.

Однородность кнопок и фильтр хвостов — раунд прототипов 19 августа 2026
(три варианта на каждую задачу, выбор по живой странице; разбор и варианты остались
архивом: https://pub.artfaal.ru/gamelog-proto-aug19/). Для кнопок принят
«рамка означает нажимается»: сначала нормировали высоту и жест наведения, потом
сняли рамку и подложку с чипов, которые ничего не делают. Отклонён третий вариант —
«статика и действия разделены»: тот же снос рамок плюс закреплённый порядок
с вертикальным разделителем, лишняя линия в и без того плотной панели.
Для фильтра принят «ярлык»: чип «без оценки» на оси оценки плюс «незакрытое»
поверх ряда статуса. Отклонены «минимум» (только «без оценки», хвосты собираются
руками) и «ряд исходов» (ряд статуса переписывается на пройдено / вернуться /
без вердикта / дроп — один клик на любой хвост, но пропадает отдельный
фильтр «сейчас играю»).

Бэклог: политика текста `make text` (штампованные концовки, цифра часов против
`hours`, вердикт дословно из текста — отчёт, как у video/image) ·
SteamGridDB для артов эксклюзивов · гистограмма распределения оценок (ждёт роста
числа записей: на семнадцати играх столбики — это те же семнадцать карточек полки,
только без обложек).

Разобрано и закрыто, чтобы не возвращалось свежей идеей: итоги года цифрами —
данных на годовой отчёт нет (порог осмысленности у Letterboxd — десять записей за
год, здесь год его не набрал), сводка за всё время дошла до прототипа и отклонена
по виду; ссылка на отдельный момент записи — отклонена в разборе 18 августа 2026;
шкала часов от HowLongToBeat — источника нет (сайт закрыт Cloudflare, официального
API не было никогда, SteamSpy время игры больше не отдаёт), и у семи игр из
семнадцати основного прохождения не существует вовсе.

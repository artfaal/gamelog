# Волна 1 — вес страницы

Дата: 2026-08-18 · Источник: аудит 7 каналов (см. `docs/specs/README.md`)

## Результат

Первый экран телефона перестаёт качать всё, что на нём не видно. Сейчас на свежей
вкладке (390×844, DPR 3, без единого скролла) приезжает 7,6 МБ в 38 запросах, из них
5,0 МБ — постеры к клипам, лежащим на четыре экрана ниже, и 2,3 МБ — постеры записей,
которые обходят `loading="lazy"` через CSS-фон. На Slow 4G это даёт LCP 32,5 с и
полную загрузку за 50,5 с. Ссылки `/e/<slug>/` ходят в телеграме, а он открывает их во
встроенном браузере на мобильной сети — то есть эти секунды видит живой читатель.
После волны на первом экране остаётся HTML+CSS+JS, шесть шрифтов и один постер:
порядка 0,4 МБ. Ни одна правка не меняет того, что видит читатель — только когда
это грузится.

## Приёмка

Готово, когда всё перечисленное верно одновременно.

1. `grep -c 'poster="' scripts/build.mjs` → `0`; `grep -c 'data-poster' scripts/build.mjs` → не `0`.
2. `grep -c -- '--poster:url' scripts/build.mjs` → `0`: переменная обоев ставится из
   `site/app.js`, а не инлайном при сборке.
3. `grep -c 'content-visibility' site/styles.css` → не `0`, и правило стоит на `article.stage`
   вместе с `contain-intrinsic-size` в форме `auto <length>`.
4. `grep -c 'saveData' site/app.js` → не `0`.
5. `fetchpriority="high"` стоит **и на логотипе первой записи** (`build.mjs:311`), а не только
   на её арте, где он уже есть (`build.mjs:333`); `grep -c 'decoding' scripts/build.mjs`
   → не менее `2` (кадр записи и карточка полки).
6. `grep -c 'requestIdleCallback' site/app.js` → не `0`.
7. `grep -c 'as="image"' scripts/build.mjs` → не `0`: preload для LCP-картинки первой записи.
   Сейчас `rel="preload"` в сборке есть, но только для шрифта (`build.mjs:454`) — картинки он не касается.
8. `make build` проходит; `node -e` по собранному `dist/index.html` показывает: атрибута
   `poster="` в разметке нет, `data-poster` есть у каждого `<video>`.
9. Замер на живой сборке (`make serve`, эмуляция 390×844 DPR 3, кэш выключен, без скролла):
   суммарный вес запросов **меньше 1,5 МБ** против нынешних 7,6 МБ. Метод замера —
   `performance.getEntriesByType('resource')`, сумма `transferSize`.
10. Глазами на `make serve`: клип по-прежнему показывает кадр-заглушку при подходе к нему,
    обои на узком экране по-прежнему собираются из трёх слоёв постера, лента листается
    без прыжков скроллбара. Кроп каждого — в отчёт.
11. Инлайновый клип встаёт на паузу при открытии лайтбокса и не возобновляется сам после
    закрытия, если до этого стоял на паузе.

## Не делаем

- Не трогаем nginx на orion — gzip и `Cache-Control` вынесены в отдельную спеку
  `2026-08-18-volna-1b-nginx.md`, потому что живут вне репозитория.
- Не пережимаем сами файлы Steam-ассетов и не меняем политику кадров/клипов.
- Не вводим сборщик, минификацию и внешние зависимости — фронт остаётся ванильным.
- Не переписываем `loading="lazy"` в разметке на что-то другое: сборка не должна знать
  про поведение, пробуждение постеров полки живёт в `site/app.js`.

## Изменяемые контракты

- **`cache/<appid>.json` — форма кэша.** Добавляется поле `posterSmall` (URL
  `library_600x900.jpg` без `_2x`). Пишет `appCache()` в `scripts/steam-app.mjs:48`.
  Существующие кэши поля не имеют — сборка обязана работать без него (fallback на `poster`),
  иначе 25 уже накопленных кэшей придётся переписывать, что запрещено каноном проекта.
  `refresh.mjs` подхватывает поле автоматически, так как форма кэша у него и у `appCache()` общая.
- **Разметка `dist/index.html`.** `poster=` → `data-poster=` у `<video>`; инлайновый
  `--poster` → `data-poster` у `article.stage`. Внешних потребителей у разметки нет,
  но OG-стабы `/e/<slug>/` собираются тем же кодом — проверить, что они не сломались.
- **Сайд-эффект.** Пока JS не выполнился, у клипов нет кадра-заглушки, а на узком экране
  нет обоев. Это осознанный размен: без JS сайт и сейчас теряет лайтбокс, полку и автоплей.

исключительно на узком экране); остальные — по одному-двум каналам.

## Сторож от регресса

Жадные постеры вернутся молча при любой правке `build.mjs`. Добавить в `make deploy`
проверку: `curl -s <SITE> | grep -c 'poster='` должно быть `0`.

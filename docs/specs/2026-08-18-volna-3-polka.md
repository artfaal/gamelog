# Волна 3 — полка: поиск, фильтр, сетка

Дата: 2026-08-18 · Источник: аудит 7 каналов (см. `docs/specs/README.md`)

## Результат

Полка (☰) перестаёт терять читателя. Сейчас несовместимые фильтры дают пустой чёрный
прямоугольник и мелкую строчку в углу; полка открывается там, где её оставили, а не там,
где читатель сейчас; включённый фильтр невидим снаружи, хотя переживает закрытие; на
телефоне половину окна занимают чипы, а до постеров надо доскроллить. Плюс полка учится
трём вещам, которых не умела: искать по текстам записей, сортировать не только по дате
и отдавать срез ссылкой.

## Приёмка

1. **S1.** Фильтр без совпадений: в сетке видимое сообщение и кнопка сброса запроса
   и фильтров; кнопка действительно сбрасывает и то, и другое.
2. **S2.** Открытие полки при чтении середины ленты: активная карточка видна без прокрутки.
   Проверка на записи из конца списка.
3. **S3.** При активных чипах кнопка ☰ несёт видимый признак, `aria-label` меняется;
   при открытой полке у кнопки `aria-expanded="true"`. Снять все чипы — признак исчезает.
4. **S5.** Нажать `9+`, затем `8+`: активен только `8+`. Пороги в одном ряду
   взаимоисключающие; чипы других рядов (часы, статус, жанр) продолжают складываться по ИЛИ.
5. **S6.** На 390×844 до сетки постеров от верха диалога меньше 300 px
   (сейчас 378 px = 49% окна). Фильтр свёрнут, если ни один чип не нажат, и раскрыт, если нажат;
   в подписи — число активных чипов.
6. **S7.** Пока в записях меньше двух закрытых лет, сетка группируется по месяцам.
   Проверка на текущих данных: групп больше одной (ожидается 6: 2026-05 — 6 записей,
   2026-07 — 3, 2026-06 — 3, 2026-01 — 2, 2026-03 и 2025-12 — по одной).
7. **S8.** Поиск находит запись по фразе из её текста, а не только по названию.
   Спойлерный текст в индекс не попадает: поиск по фразе из-под спойлера не находит ничего.
8. **S9.** Переключение порядка: дата / оценка / часы. Если порядок не по дате, заголовки
   групп не врут (либо скрыты, либо заменены).
9. **S10.** Выбранный фильтр отражается в hash; открытие такой ссылки в чистой вкладке
   открывает полку с тем же срезом.
10. **S12.** В поле поиска: Escape при непустом запросе очищает его и оставляет полку открытой;
    Escape при пустом поле закрывает полку.
11. **S13.** Сетка прокручена до низа — лента под модалкой не двигается.
12. `make check` чист, `make build` проходит. Пороги чипов по-прежнему заданы в одном месте —
    в `scripts/build.mjs` и приезжают в разметку атрибутами — второй копии в `app.js` не появилось.

## Не делаем

- **Не трогаем жанровые чипы** (S4 отклонён при разборе): правило покрытия и ручная
  простановка `genres:` не делаются. Действующий стоп-лист `GENRE_STOP` остаётся как есть.
- **Не подписываем карточки без постера** (S11 отклонён).
- Не сбрасываем выбранные чипы при закрытии полки: фильтр — режим просмотра, это
  осознанное решение (README). Сбрасывается только строка поиска.
- Не вводим индекс поиска отдельным файлом: корпус 12 КБ после схлопывания пробелов,
  он ложится в атрибуты карточек.

## Изменяемые контракты

- **Разметка карточки полки.** Добавляется атрибут с текстом записи для поиска
  (без спойлеров) и, при необходимости, атрибуты порядка. Пороги чипов
  (`data-k/min/max/v`) не меняются.
- **URL.** Появляется hash-параметр среза фильтра. Существующие якоря записей
  (`#<slug>`) обязаны продолжать работать: `games.artfaal.ru/#hades` — публичная ссылка,
  на неё же ведут OG-стабы `/e/<slug>/`. Разбор hash должен различать якорь записи и срез фильтра.
- **Сайд-эффект S7.** Группировка по месяцам — временный режим. Условие переключения
  на годы задаётся в одном месте и описывается в README, иначе через год никто не вспомнит,
  почему сетка группируется странно.

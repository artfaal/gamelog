# Волна 4 — лента, лайтбокс, доступность

Дата: 2026-08-18 · Источник: аудит 7 каналов (см. `docs/specs/README.md`)

## Результат

Читатель перестаёт теряться в ленте длиной 38 380 px и получает работающую клавиатуру.
Сейчас в ленте нет ни одного указателя, где он находится, хотя данные для ответа уже
посчитаны — `IntersectionObserver` знает текущую запись и подсвечивает её карточку в полке,
но наружу это не выходит. Клик в полке улетает плавным скроллом через всё содержимое.
Кнопка «поделиться» выглядит чипом, а область нажатия у неё 13×13 px, и ошибка копирования
проглатывается молча. В лайтбоксе подпись спорит со счётчиком, фокус после закрытия падает
в никуда, а смена кадра не объявляется скринридеру.

## Приёмка

1. **U1.** В шапке видно положение: номер записи из общего числа и её название; значение
   меняется при прокрутке. Шапка не перекрывает содержимое (проверить на узком экране).
   Полоска прогресса чтения — если делается, то под `prefers-reduced-motion` не анимируется.
2. **U2.** `grep -c 'scroll-behavior: *smooth' site/styles.css` → `0` в правиле `html`.
   Клик по карточке полки переносит к записи сразу, без пролёта. Кнопка «наверх»
   по-прежнему едет плавно (она передаёт `behavior` руками, `app.js:277-280`), стрелки
   в полке тоже (`app.js:146`).
3. **U3.** В хвосте ленты стоит стена постеров. Проверка на дублирование разметки:
   `grep -c 'shelf__list' dist/index.html` → `1` — узел один и переносится, а не копируется.
   Полка после открытия и закрытия по-прежнему работает, стена возвращается на место.
4. **U4.** При системном увеличении текста до 200% шапка переносится, счётчик не обрезан.
   Кроп на 1440×900 при 200%.
5. **M2.** Кнопка «поделиться» — область нажатия не меньше 32×32 px (замер `getBoundingClientRect`).
   Ошибка копирования сообщается читателю: сейчас `catch { return; }` глотает её молча
   (`app.js:192`). Успех уже сообщается через `say()` — этот путь не трогать, только проверить.
6. **M4.** Открыть кадр с клавиатуры, закрыть Escape — фокус вернулся на кнопку-кадр,
   а не на `body`. Проверить и на кадре, удалённом из DOM (спойлер закрылся) — без ошибки в консоли.
7. **M5.** При листании стрелками скринридер объявляет смену кадра. Формулировка счётчика
   уже человеческая («1 из 2», `app.js:221`) — нужна только live-область: сейчас смена
   происходит молча. Проверка VoiceOver.
8. **A1.** Под `prefers-reduced-motion: reduce` переходов не видно:
   `grep -c '0.01ms\|1ms' site/styles.css` в этом медиа-запросе → не `0`.
9. Клавиатурный прогон всей страницы: фокус виден на каждом интерактивном элементе,
    полка и лайтбокс достижимы, из обоих выходят по Escape, фокус не убегает за модалку.
10. `make check` чист, `make build` проходит.

## Не делаем

- **Не делаем ссылку на отдельный момент** (M1 отклонён при разборе), хотя она стоит
  в бэклоге README и работы там немного.
- **Не добавляем расшифровку клипа с речью** (M6 отклонён).
- **Не трогаем подписи карточек полки** (A2 отклонён при разборе, но фактически уже сделан
  коммитом `c2ef349`: оценка и часы уходят скринридеру).
- Не вводим scroll-snap: лента — лонгрид, а не карусель.
- Не переделываем лайтбокс на новый компонент — правки точечные.

## Изменяемые контракты

- **Шапка становится sticky** (для U1). Это меняет геометрию первого экрана: проверить,
  что логотип записи и медаль оценки не уезжают под неё, и что на узком экране шапка
  не отъедает высоту у постера-обоев.
- **Разметка кнопки «поделиться»**: `<span class="chip chip--btn"><button>` → полноценная
  кнопка-чип. Обработчик в `app.js:184` продолжает находить её по классу `.share` и
  читать `data-slug`/`data-name`.
- **Хвост `<main>`**: добавляется секция со стеной постеров. Узел общий с полкой —
  переносится `appendChild` при открытии и возвращается при закрытии. Второй разметки
  быть не должно: иначе появится два места для одного факта.
- **Сайд-эффект U2**: снятие глобального `scroll-behavior` разблокирует V8 из волны 2
  (переход полка → запись). Если волна 2 уже прошла и V8 был отложен — вернуться к нему.
